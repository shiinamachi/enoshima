# User configuration instructions

- Keep selected user state in chezmoi source form under `home/`; do not add
  mutable documents, credentials, caches, or machine observations.
- For any visible or interactive change, invoke `$design-taste-frontend` and
  `$ui-ux-pro-max`, read `docs/DESKTOP-UI-CONCEPT.md`,
  `docs/DESKTOP-UX-REFERENCES.md`, the surface entry in
  `docs/ui-surfaces.yaml`, and its specific concept document.
- Use the existing Hyprland/QML/GTK CSS/Waybar/SwayNC/Hyprlock stack. Do not add
  web frameworks, remote fonts, CDNs, generated design-system packages, or a
  parallel persisted token system.
- If a repository-rendered visible state lacks an approved concept, invoke
  `$enoshima-concept-art` with image generation and complete its candidate,
  selected-direction, redline, asset, and manifest workflow before UI code.
  Use an `external_surfaces` contract without concept art only when an upstream
  application owns every rendered pixel and lifecycle; preserve its named T5
  physical gate and do not treat VM evidence as acceptance.
- Validate affected state, English/Korean localization, required scales,
  keyboard and pointer interaction, clipping, accessibility, and purposeful
  motion. Run `scripts/check-ui-concept-coverage` and the focused checks chosen
  by the repository selector.
- Treat VM screenshot pixels as review evidence, not golden tests. Preserve the
  documented internal/external physical-display review as a T5 gate.
